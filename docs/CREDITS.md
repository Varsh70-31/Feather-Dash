# Credits, asset provenance and licences

This file is the commercial record of where every byte in Feather Dash came from. If someone asks
"do you have the right to sell this?", this is the answer, and the claims in it are checkable
rather than asserted — `tests/test_docs.py` re-reads the font's own metadata and the repository
layout and fails if anything here drifts.

## Art

**Every image in the game is an original work generated by code in this repository.** No sprite,
texture, backdrop, icon or logo was downloaded, bought, traced from, sampled from, or derived from
any third-party image. There is no asset pack, no stock library, no AI image model and no reference
photograph anywhere in the pipeline.

The art is drawn from geometric primitives — gradients, ellipses, polygons, value noise, blurs —
by these scripts:

| Script | What it produces |
| --- | --- |
| [`tools/artlib.py`](../tools/artlib.py) | The drawing primitives everything else is built from: supersampled canvases, rounded shapes, tileable value noise, ridge profiles, gradients |
| [`tools/gen_bird.py`](../tools/gen_bird.py) | The player character: 6 skins x 4 wing-cycle frames |
| [`tools/gen_world.py`](../tools/gen_world.py) | Sky gradients, far/mid/near parallax layers, ground strips and clouds for all 4 themes |
| [`tools/gen_brand.py`](../tools/gen_brand.py) | Store icon, Android adaptive icon layers, monochrome themed icon, presplash and feature graphic |

The evidence that these are original works is unusually strong, and worth keeping: the *source
code that draws each pixel* is in the repository, the output is deterministic, and anyone can
delete `assets/images/` and regenerate it byte-for-byte. A traced or sampled asset cannot be
reproduced that way.

Three practical consequences:

1. **A buyer of this project owns the art outright.** There is no licence to transfer, no
   attribution to preserve, and no asset-store EULA restricting resale or modification.
2. **Restyling is a code change, not a commission.** Recolouring every theme means editing
   `THEME_PALETTE` in [`tools/manifest.py`](../tools/manifest.py) and re-running one script.
3. **It is the defence if the listing is ever challenged** in a genre known for clones. See
   [PLAY_STORE_SUBMISSION.md](PLAY_STORE_SUBMISSION.md#8-the-real-risk-for-this-app).

## Audio

**Every sound in the game is synthesised from scratch by
[`tools/gen_audio.py`](../tools/gen_audio.py)** — no sample library, no "royalty-free" download, no
field recording, no AI audio model. Each waveform is computed from NumPy primitives: oscillators,
FFT filtering, envelopes and soft-clipping.

| Output | What it is |
| --- | --- |
| `assets/audio/<name>_<i>.wav` | Sound effects — flap, score, coin, streak, hit, fall, best, medal, unlock, countdown and UI taps, several with pitch variants |
| `assets/audio/music_<theme>.wav` | One seamless looping music bed per theme, 8 bars each, 100–118 bpm |
| `assets/audio/index.json` | Which variants exist and how to pick between them, written so the runtime can read it with the standard library alone |

The music loops are periodic *by construction* rather than crossfaded: notes are rendered into a
fixed-length buffer with wrap-around indexing, so the release tail of the last chord is literally
the same continuous waveform that occupies the start of the file. The generator measures the join
and fails if it is not continuous.

Same commercial consequence as the art: there is nothing to licence, nothing to attribute, and a
buyer owns the soundtrack outright.

> If audio is ever added from *anywhere else* — a sample pack, a Creative Commons library, an AI
> audio tool — record the exact source URL, the licence, its version, whether attribution is
> required, and whether redistribution inside an app store listing is permitted. Many "free" sound
> libraries forbid exactly that, and an undocumented sound file is the most likely way for an
> otherwise clean project to acquire a licensing problem.

| **Licence** | **SIL Open Font License, Version 1.1** |
| Licence URL | <http://scripts.sil.org/OFL> |

These values were not taken from a web page — they were **read out of the font binary's own `name`
table** (name IDs 0, 8, 9, 13 and 14), which is why they can be trusted and why the self-test can
re-verify them on demand.

### What the OFL 1.1 allows

It is a permissive, free-software-style font licence, and it is friendly to exactly this use case:

- The font may be **used, studied, modified and redistributed freely**.
- It may be **bundled inside, and sold with, software** — including a paid app, a commercial game,
  or a project sold to a client. The OFL explicitly permits this.
- It may be **embedded in a document or an application** without the document or application
  inheriting the licence. The OFL does not infect your game's own code or art.

### What the OFL 1.1 requires of you

1. **Distribute the copyright notice and the licence text with the font.** This is the main
   obligation, and the only one that takes any action — see below.
2. **Do not sell the font on its own.** Selling a game that contains it is fine; selling the `.ttf`
   as a font product is not.
3. **Keep modified versions under the OFL**, and do not use a Reserved Font Name for a modified
   version. The Bai Jamjuree copyright line declares **no** Reserved Font Name, so a renamed
   derivative would be permissible — but this project ships the font unmodified, so the question
   does not arise. Do not subset, re-hint or convert the file without re-checking this.
4. **Do not imply endorsement** by Cadson Demak or Katatrad Aksorn.

### Licence obligations: satisfied

The OFL 1.1 text ships at [`assets/fonts/OFL.txt`](../assets/fonts/OFL.txt), beside the font it
covers, so any packaging step that bundles `assets/` carries the licence with it and anyone who
copies the font out of the project takes the licence too. `txt` is included in
`source.include_exts` in [`buildozer.spec`](../buildozer.spec), so the file reaches the device
rather than being silently dropped from the bundle. The attribution is shown in-app on the
Settings screen, and the font is shipped unmodified under its original name.

To verify after a release build, unzip the AAB and confirm `assets/fonts/OFL.txt` is present.

The former duplicate at `Fonts/BaiJamjuree-Bold.ttf` (byte-identical, MD5
`259fb8f05fef8dd052def841337c0821`) is a version 1 leftover — see below.

## Removed version 1 assets

> **These have been removed from the repository and must stay out of it.**
> `tests/test_docs.py` fails if any of them comes back.

The version 1 game shipped with assets whose provenance is not documented anywhere in this
repository:

| Path | Contents | Provenance |
| --- | --- | --- |
| `Images/` (removed) | `background.png`, `ground.png`, `pipe_up.png`, `pipe_down.png`, `player.png` | **Unknown.** Not generated by anything in `tools/`. |
| `Sounds/` (removed) | `score.wav`, `slap.wav`, `woosh.wav` | **Unknown.** No source, no licence, no receipt. |
| `Fonts/` (removed) | A second, byte-identical copy of the Bai Jamjuree font | OFL, but redundant |

The 2.0 game does not load any of them — `featherdash/platform.py` resolves assets only under
`assets/` — and `buildozer.spec` already lists `Images`, `Sounds` and `Fonts` in
`source.exclude_dirs`, so none of them reaches a device. Two reasons they must stay out:

1. **Licensing.** Undocumented art and audio are an unquantifiable liability in a product you
   intend to sell. "I do not know where it came from" is not a defence, and a buyer doing due
   diligence will ask.
2. **Genre risk specifically.** The removed `Images/pipe_up.png` was a green striped pipe, the single
   most recognisable visual element of the game this genre is accused of cloning. It is not used by
   Feather Dash, but leaving it in a repository you hand to a client — or in a build you upload —
   is an avoidable invitation. See
   [PLAY_STORE_SUBMISSION.md](PLAY_STORE_SUBMISSION.md#8-the-real-risk-for-this-app).

The version 1 code has been moved out of the repository as well, so everything in it belongs to
the 2.0 game.
