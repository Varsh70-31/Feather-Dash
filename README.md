# Feather Dash

A one-tap arcade flyer in Python and pygame, built to ship: resolution-independent rendering that
fits any screen without letterboxing, fixed-timestep physics that feels identical at 60, 90 or
120 Hz, and every pixel and sample in it generated by original code in this repository, so there is
no third-party asset licence anywhere in the product.

unlockable birds, five medals, and a difficulty curve that tightens over the first 42 points and

## What it is

A complete, commercial-grade mobile game, not a tutorial project. It runs on a desktop window you
can resize to any shape while playing, and it packages to a signed Android App Bundle ready for the
Google Play Store. The repository contains the game, the generators that draw and synthesise its
assets, the Android build toolchain, the test suite, and the store material needed to publish it.

Version 2.0.0 is a complete rebuild of the original single-file `main.py`.

## Features

**Gameplay**

- One-tap flight with a forgiving elliptical hitbox deliberately smaller than the sprite, so a near
  miss reads as a near miss rather than a cheap death.
- A **dash**: a short forward burst that covers 178 world units in about a quarter of a second,
  nearly weightless so the bird holds its line, on a 1.45-second cooldown shown as an arc around
  the button. It grants no invulnerability — dashing into a pillar still kills — so it stays a
  decision rather than an escape hatch.
- A **game-speed setting** from 0.5× to 4×, anchored to version 1's actual pace
  (`config.LEGACY_SPEED` = 259.2 world units/s, derived from v1's 2.4 px/frame at 60 fps in a
  600 px window). Eight labelled presets from Relaxed to Insane; the 1.25× default reproduces the
  hand-tuned curve, and 1.0× is the original game's speed exactly.
- A difficulty curve that interpolates gap size (400 → 302 world units), pillar spacing
  (430 → 372) and scroll speed (322 → 476 units/s) across the first 42 points, with a cap on how
  far consecutive gaps may move so the game stays readable.
- Four themes — dawn, day, dusk, night — rotating every 12 points with a 2.2-second cross-fade
  across all four parallax layers, the sky and the ground.
- Feather tokens in roughly 62% of gaps, with a bonus for collecting five in a row; feathers unlock
  six bird skins at 0 / 150 / 300 / 600 / 1200 / 2400. Everything is earned by playing: there are
  no in-app purchases and no currency to buy.
- Five medals at 10, 25, 50, 100 and 200 points.
- Pause on focus loss, so backgrounding the app does not kill a run.

**Presentation**

- Four scrolling parallax bands plus clouds, a gradient sky and a textured ground, all tiling
  seamlessly and all theme-aware.
- A pooled particle system that allocates nothing during play, camera shake, hit-stop on death, and
  easing curves that overshoot where overshoot reads as weight.
- Interface laid out in world units against the device's **safe area**, so the score and the
  buttons stay clear of camera cutouts, status bars and gesture handles.
- Procedurally synthesised audio: layered sound effects with pitch variants, and a seamless looping
  music bed per theme.

**Engineering**

- Resolution-independent world-unit rendering (see below) — one build, every aspect ratio.
- Fixed 120 Hz simulation with interpolated rendering.
- Atomic, versioned, migrating save file that degrades to defaults rather than crashing and runs
  in memory on a read-only filesystem.
- Unified input: keyboard, mouse, touch and gamepad, with SDL's synthetic touch-mouse events
  de-duplicated in one place.
- Every asset loader degrades instead of raising — a missing image renders as a magenta placeholder
  so the game keeps running and the mistake is obvious on screen rather than a stack trace in a
  player's hands.
- No runtime dependency beyond pygame. NumPy and Pillow are used only by the asset generators and
  are never imported by the game, so they are not in the Android bundle — a contract the test suite
  enforces.

## How it is built

**Resolution independence.** The game is authored entirely in *world units*, never pixels. The
world is always `WORLD_H = 1080` units tall; the viewport works out how many units wide the current
display is worth and clamps that between 560 and 1040 so an ultra-wide window cannot see so far
ahead that it becomes an advantage. Vertical scale is therefore constant — a gap is the same
fraction of screen height on every device, and the game is exactly as hard on all of them — while a
wider screen simply shows more scenery. Surplus display beyond the clamp becomes *overscan*: the
backdrop is drawn across the whole screen while gameplay stays inside the guaranteed box, so there
are never black bars and never stretched art. Everything renders straight to the window at its
native resolution, with no intermediate low-res canvas, so output is crisp at any size including
HiDPI. See [`featherdash/display.py`](featherdash/display.py).

**Fixed-timestep physics.** Simulation advances in fixed 1/120 s slices through an accumulator, and
rendering interpolates between the last two slices. The feel is therefore identical on a 60 Hz
phone, a 90 Hz mid-ranger and a 144 Hz monitor, while motion stays smooth at whatever rate the
panel refreshes. A long stall — a breakpoint, or the app resuming from the background — is clamped
rather than simulated all at once, so the player never dies while they were away. See
[`featherdash/app.py`](featherdash/app.py).

**Original art and audio, generated by code.** Every image and every sound is computed by the
scripts in [`tools/`](tools/) from drawing and DSP primitives: no sampled, traced, downloaded,
purchased or AI-generated media is involved anywhere in the pipeline. Delete `assets/` and it
regenerates byte-for-byte. Commercially this is the point — the art carries no licence, no
attribution requirement and no asset-store EULA, so whoever owns this project owns all of it
outright. The only third-party creative asset in the game is the Bai Jamjuree typeface, which is
under the SIL Open Font License; see [`docs/CREDITS.md`](docs/CREDITS.md).

**Android packaging.** A reproducible, Docker-based buildozer / python-for-android toolchain lives
in [`packaging/android/`](packaging/android/), driven by a single script. It targets API 36, builds
`arm64-v8a` and `armeabi-v7a`, and produces a Play-ready signed `.aab`.

## Screenshots

The eight store captures live in `store/screenshots/` and are produced by:

```bash
.venv/bin/python tools/screenshot.py              # the eight phone shots, 1080 x 1920
.venv/bin/python tools/screenshot.py --tablet     # ...and the tablet set, 1600 x 2560
```

They are captured, not played. The tool boots the real game at store resolution, forces each scene
into a specific state, steps the simulation a fixed number of times and saves the frame — so the
listing always shows the actual renderer. The four non-gameplay shots (menu, results, shop,
settings) come out byte-identical every run; the four gameplay shots are **re-rolled** each run,
because the simulation's RNG is unseeded, so pillar gaps, coin placement and particle spray differ.
Check those four against their spec before you upload them. What each shot has to contain, the
caption that goes with it, and how to make the gameplay shots reproducible are in
[`store/screenshots.md`](store/screenshots.md).

*(A `make screenshots` wrapper around that command is the obvious next line in the Makefile; it is
not there yet.)*

## Install and run

Requires **Python 3.9 or newer**. The only runtime dependency is pygame.

```bash
git clone <this-repo> featherdash && cd featherdash

python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python main.py                     # or: make run
```

The window opens at 480 x 854 and is freely resizable — drag it to any shape while playing to see
the world-unit layout adapt. `F11` toggles fullscreen.

To work on the asset generators or run the test suite you also need the build-time tools, which are
kept separate precisely so they never reach the Android bundle:

```bash
make dev                           # or: pip install -r requirements-dev.txt
```

`make` on its own lists every target.

Two environment variables are useful during development:

| Variable | Effect |
| --- | --- |
| `FEATHERDASH_SAFE_INSETS=l,t,r,b` | Simulate a phone's cutout insets, in world units, on desktop |
| `SDL_VIDEODRIVER=dummy SDL_AUDIODRIVER=dummy` | Run headless, as the tests and CI do |

## Controls

Two actions, many ways to perform each.

| Action | Keyboard | Pointer | Gamepad |
| --- | --- | --- | --- |
| Flap / start / confirm | `Space`, `↑`, `W`, `Enter` | Left click, or tap anywhere | `A` / `✕` |
| Dash | `D`, `→`, `Shift`, `E` | On-screen dash button (touch only) | `X` / `□` |
| Back / menu | `Esc`, `Backspace`, Android back | — | `B` / `○` |
| Pause | `P`, `Tab` | Pause button | `Start` |
| Fullscreen | `F11`, `Alt`+`F` | — | — |
| FPS and viewport overlay | `F3` | — | — |
| Quit | `Ctrl`/`Cmd`+`Q` | Window close | — |

On touch devices SDL also fabricates mouse events from every tap;
[`featherdash/input.py`](featherdash/input.py) discards those in one place so a single tap can
never register as two flaps.

## Regenerating the assets

`assets/images/` and `assets/audio/` are generated, not hand-authored. Nothing is lost by deleting
them. Each generator verifies its own output and exits non-zero if a check fails — sizes, alpha
ranges, seamless tiling, loop continuity, adaptive-icon safe circles.

```bash
make assets                             # everything, in order

.venv/bin/python tools/gen_bird.py      # player sprites
.venv/bin/python tools/gen_world.py     # skies, sun/moon, stars, parallax, ground, clouds
.venv/bin/python tools/gen_props.py     # pillars, coins, particle textures
.venv/bin/python tools/gen_ui.py        # panels, buttons, icons, medals, logo
.venv/bin/python tools/gen_audio.py     # sound effects and music beds
.venv/bin/python tools/gen_brand.py     # store and launcher artwork
```

[`tools/manifest.py`](tools/manifest.py) is the single source of truth for the art: every filename,
every source pixel size, the theme palettes and the skin colours. Change a palette there, re-run
one script, and the whole game is restyled. `featherdash/config.py` holds the subset of that
contract the running game needs, and `tests/test_contract.py` fails if the two ever drift apart.

Sizes in the manifest are *source* dimensions, authored at roughly twice their largest on-screen
size; the game scales them down for the device it is on and caches the result.

## Building for Android

buildozer does not run on macOS, so the build happens inside a pinned Docker image. One script
drives all of it:

```bash
make android-debug        # debuggable APK into ./bin
make android-install      # adb install it onto a connected device
make android-logcat       # tail the game's log from the device
make android-release      # signed .aab for Google Play
make android-validate     # check buildozer.spec against the real buildozer
make android-clean        # drop build output (make distclean drops the SDK caches too)
```

Each is a thin wrapper over `packaging/android/build.sh <command>`, which can also be run directly.

A release build needs an upload keystore. Create one once, outside the repository:

```bash
make keystore             # or: packaging/android/make_keystore.sh
export FEATHERDASH_KEYSTORE=/absolute/path/to/upload.keystore
export FEATHERDASH_KEYSTORE_PASSWORD='...'
export FEATHERDASH_KEY_ALIAS=upload
export FEATHERDASH_KEY_PASSWORD='...'
```

The keystore is bind-mounted read-only for the duration of the build and the passwords are passed
through the environment, so neither is baked into the image or written to disk. **Never commit a
keystore.** The first cold build takes around 45 minutes while the SDK, NDK and a cross-compiled
CPython are assembled; warm builds take about three.

Key settings in [`buildozer.spec`](buildozer.spec): package `com.varshraj.featherdash`, target API
36, minimum API 24, `arm64-v8a` + `armeabi-v7a`, release artifact `aab`, portrait, fullscreen, and
exactly one permission — `VIBRATE`, for the haptic tick on tap. The version is read straight out of
`featherdash/__init__.py`, so it is bumped in one place.

Publishing it is a separate project in itself; the full operator checklist, including the 14-day
closed-testing requirement that catches new developer accounts out, is in
[`docs/PLAY_STORE_SUBMISSION.md`](docs/PLAY_STORE_SUBMISSION.md).

## Tuning the game

Everything that decides how the game feels is a named constant in
[`featherdash/config.py`](featherdash/config.py), in world units per second rather than pixels per
frame. The ones worth reaching for first:

| Constant | Default | What it changes |
| --- | --- | --- |
| `GRAVITY` | 4300 | How fast the bird falls |
| `FLAP_VELOCITY` | −1280 | How hard a tap launches it |
| `GAP_START` → `GAP_END` | 400 → 302 | The vertical opening, easiest to hardest |
| `SPEED_START` → `SPEED_END` | 322 → 476 | Scroll speed, easiest to hardest |
| `RAMP_SCORE` | 42 | The score at which the curve reaches its hardest values |
| `BIRD_HIT_RX` / `BIRD_HIT_RY` | 30 / 26 | The forgiveness of the hitbox |
| `COIN_CHANCE` | 0.62 | How often a gap carries a feather |
| `THEME_EVERY` | 12 | Points between theme changes |
| `MEDAL_THRESHOLDS` | 10…200 | Medal scores |
| `WORLD_W_MIN` / `WORLD_W_MAX` | 560 / 1040 | The clamp on how wide the play area may get |

After changing anything in the difficulty block, run the autoplay bot (below): it is the fastest
way to find out whether the game is still winnable.

## Testing

Everything runs headless, which is also how CI runs it.

```bash
make test     # the suite
make lint     # ruff, plus a shell syntax check on the build scripts
make check    # lint + tests + the packaging self-test — everything CI does

# without make:
SDL_VIDEODRIVER=dummy SDL_AUDIODRIVER=dummy .venv/bin/python -m pytest tests/ -q
```

| Suite | What it covers |
| --- | --- |
| `tests/test_contract.py` | The runtime constants in `config` match the authoring contract in `tools/manifest.py`, and the game never imports a build-only module |
| `tests/test_display.py` | The world-unit mapping across aspect ratios, clamping, overscan and safe areas |
| `tests/test_gameplay.py` | The simulation: scoring, collisions, the difficulty curve, pickups |
| `tests/test_save.py` | Atomic writes, migration, corrupt-file recovery, read-only filesystems |
| `tests/test_audio.py` | The generated WAVs and the runtime audio layer, including its degradation to silence |
| `tests/test_fx.py` | The particle pool, camera and easing curves |
| `tests/test_ui.py` | Safe-area layout, text sizing and the widgets |
| `tests/test_docs.py` | The documentation and store copy: character limits, licence facts, quoted constants, internal links |
| `tests/autoplay.py` | A headless bot that plays the game at several viewport shapes — if a straightforward controller cannot survive, the physics or the difficulty ramp is broken |

```bash
SDL_VIDEODRIVER=dummy SDL_AUDIODRIVER=dummy .venv/bin/python tests/autoplay.py
```

Each asset generator is also its own test: run it and it verifies what it produced.
